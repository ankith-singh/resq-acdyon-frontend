# DECISIONS

## 1. Why this approach?

I chose React + Vite + Tailwind CSS because the challenge is focused on shipping a polished, responsive product experience rather than building a large backend system. This stack allowed me to iterate quickly while keeping the UI component-based and maintainable.

I designed RESQ as a disaster-response coordination platform with a dark operational interface. The hero communicates the product value immediately, while the Command Center provides an actual representation of the product instead of relying only on marketing copy.

I intentionally avoided fabricated testimonials, customer logos, and unsupported statistics. The dashboard data is explicitly presented as fictional demo data.

## 2. Trade-off under the time limit

The main trade-off was prioritizing the core landing-page experience and responsive behavior over building a functional backend or authentication system.

With a full week, I would connect the Command Center to a real data source, add authentication and role-based access, improve accessibility testing, add automated UI tests, and validate the design with real users.

## 3. AI usage

I used AI assistance during development for implementation guidance, debugging, responsive-layout decisions, and reviewing parts of the React/Tailwind implementation.

I personally integrated and tested the suggestions, verified the application locally, corrected implementation details when necessary, and ran the production build successfully with Vite.

The final UI decisions, product concept, content direction, responsive behavior, and implementation verification were reviewed by me before submission.
